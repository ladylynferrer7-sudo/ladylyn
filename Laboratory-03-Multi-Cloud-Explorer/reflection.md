# Mission Reflection

*1. Which cloud platform impressed you the most?*

AWS impressed me the most out of the three. What stood out wasn't just its size — 200+ services — but how that size actually plays out: almost any cloud pattern I researched, from simple VM hosting to auto-scaling for global traffic, already had a mature, well-documented AWS service built for it. Researching the Client A (startup) and Client D (global e-commerce) scenarios made this concrete: AWS had a strong, specific answer for both a budget-conscious small company and a massive worldwide operation, without needing to reach for a different provider for either one.

*2. What similarities exist among AWS, Azure, and GCP?*

Despite different names and consoles, all three providers offer the same core building blocks: virtual machine compute (EC2, Virtual Machines, Compute Engine), object storage (S3, Blob Storage, Cloud Storage), virtual networking (VPC, VNet, VPC), identity and access management, managed SQL databases, and managed Kubernetes. All three also run on a pay-as-you-go pricing model. This means the underlying cloud computing concepts are portable — once you understand one provider's structure, mapping to the other two is mostly a matter of learning new names for familiar ideas.

*3. How do business requirements influence cloud platform selection?*

The client scenarios in this lab made it clear that "best" cloud provider isn't a fixed answer — it depends entirely on the problem being solved. A university already running Active Directory and Microsoft 365 gets far more value from Azure's native integration than from AWS's larger catalog. An AI research company needs GCP's TPUs and Vertex AI more than it needs broad service variety. Budget, existing technology stack, growth expectations, and specific technical needs (like high-performance ML computing) all push the decision in different directions.

*4. What did you learn from acting as a Cloud Solutions Consultant?*

I learned that the job isn't to pick a favorite platform and recommend it everywhere — it's to analyze what a specific client already has and actually needs, then match that to the provider whose strengths line up. That's a different mindset than just comparing feature lists.

*5. How has your GitHub Cloud Computing Portfolio improved after completing this mission?*

My portfolio now includes a full multi-cloud research and recommendation package — three provider research docs, a comparison and service-matching table, and a client recommendation report with a decision matrix — real evidence I can evaluate cloud platforms against actual business requirements, not just describe what each one does.
